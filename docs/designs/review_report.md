* **Review Methodology**: Adversarial Zero-Context Goldfish Audit inspired by Google's [Elephant-Goldfish Model (EGM)](https://github.com/google/elephant-goldfish-model). Conducted by spawning an isolated zero-context review subagent (`rubber-duck`, reading strictly the markdown specification files above with zero access to `crates/**` or prior review notes) alongside independent cross-session Goldfish design critique—without invoking external EGM CLI plugins.
* **Gate Status**: Phase 0 is a specification review. The Goldfish notes resolved findings `B1`–`B18` and `N1`–`N5` in the design text. That review is not a first-launch acceptance of the running tree.

## 1. Phase 0 Full-Suite Goldfish Audit (`B1`–`B18` Blocking Findings)

| ID | Area | Adversarial Failure Trace Found by Zero-Context Reviewer | Specification Resolution Applied |
| :--- | :--- | :--- | :--- |
| **B1** | `metadb-storage` / MVCC Cut | Defining snapshot visibility solely by `v.hlc <= read_hlc` allows a concurrent `RaftStateMachine::apply(I+1)` with `hlc <= external_read_hlc` to become visible mid-scan after key `A` was already skipped; `SnapshotGuard` also needed to pin `Arc<Version>` + `Vec<Arc<ImmMemTable>>` with bounded per-page step leases. | Defined immutable **`ReadCut { max_raft_index, max_hlc }`** pinned alongside `(Arc<Version>, Vec<Arc<ImmMemTable>>, Arc<ActiveMemTableHandle>)` with `<100µs` per-page step leases. Separated `acquire_linearizable_snapshot(min_read_index)` from `acquire_fixed_snapshot(barrier_hlc)` (preceded by `clock.update_checked(barrier_hlc)` + `ReadIndex`). Visibility checks `v.raft_index <= g.cut.max_raft_index` (`storage_lsm_mvcc.md` §6.1). |
| **B2** | `metadb-core` / Total Order | Non-decreasing HLC timestamps left same-HLC tie ordering undefined for MemTable version collapse, `_attr_` reconciliation, and cross-shard `SecondaryIndexTable` updates. | Enforced strict `(entry_hlc, log_index)` monotonicity in `apply` (`consensus_and_transactions.md` §5.1) and total tuple ordering `(hlc, origin_shard_id, origin_raft_index, task_ordinal)` for `SecondaryIndexTable` (`consensus_and_transactions.md` §7.3). |
| **B3** | `metadb-storage` / Wire Grammar | `DEVELOPMENT_PLAN.md` referenced a `48-byte` SSTable footer while `storage_lsm_mvcc.md` defined `64` bytes; `IndexBlock`, `MetaBlock`, and `SstFileMeta` variable-length fields lacked explicit length framing; non-final `MANIFEST` corruption handling was under-specified. | Standardized on the **64-byte** footer across all specs; specified exact byte-level `u32 LE` length framing for `IndexBlock`, `MetaBlock`, and `VersionEdit`/`SstFileMeta`; mandated that only a torn final EOF record may be truncated while any non-final CRC/grammar error fails with `ManifestCorrupted` (`storage_lsm_mvcc.md` §7.2–§7.3, `DEVELOPMENT_PLAN.md` Phase 2). |
| **B4** | `metadb-storage` / Compaction | Overlapping `L0` SSTables lacked a persisted flush sequence for deterministic shadowing, and range compactions straddling `[start_key, end_key)` needed explicit full-input rewrite and outer-key tombstone preservation rules. | Added monotonic `flush_generation: u64` to `SstFileMeta`, `MetaBlock`, and `VersionEdit`; defined deterministic merge precedence (`ActiveMemTable > ImmMemTables > L0 desc flush_generation > L1 > L2 > L3`); mandated full rewrite of participating input SSTables while checking `Version::has_overlap_above` for outer boundary tombstones (`storage_lsm_mvcc.md` §7.3, §8.2). |
| **B5** | `metadb-raft` / WAL-less Replay | `PreFlushHook::on_seal_memtable(M)` reading `VersionSet` alone could miss earlier queued `ImmMemTable` baselines, and OpenRaft `applied_state()` / `last_committed` startup recovery contract was not explicitly anchored to `MANIFEST`. | `on_seal_memtable(M)` now reads `ViewAtRaftIndex(M)` across `SealingMemTable + ImmMemTables + VersionSet`. `HARD_STATE` durably persists `last_committed`; `MANIFEST` persists `DurableShardCheckpoint`, and `applied_state()` reports `flushed_raft_log_id (F)` on startup so OpenRaft replays `(F ..= last_committed]` (`storage_lsm_mvcc.md` §6.3, §7.3; `consensus_and_transactions.md` §5.1–§5.2). |
| **B6** | `metadb-raft` / Snapshots | Hard-linked SSTable snapshots could mismatch `Version.flushed_raft_index` if concurrent entries applied during flush, and learner `install_snapshot` lacked atomic directory swap and queue rehydration rules. | Mandated `snapshot_index = checkpoint_version.flushed_raft_index` strictly, durable `snap_<S>.tmp -> snap_<S>` creation, and atomic `lsm_installing_<S> -> lsm` installation on learners with full `[0x07]` `AuxOutbox` rehydration (`consensus_and_transactions.md` §5.3). |
| **B7** | `metadb-tx` / `[0x07]` Keying | Keying `[0x07] SpilledAuxOutbox` solely by `[0x07][origin_raft_index: 8B BE]` causes same-entry tasks (`CreateFile`'s `QuotaDelta` + `IndexUpsert`, `chown` dual deltas, overwrite `Rename` triple tasks) to overwrite one another. | Changed `[0x07]` key layout to **`[0x07][origin_raft_index: u64 BE][task_ordinal: u16 BE]`** (`11B`) across `Architecture.md` §4 and `consensus_and_transactions.md` §7.3. |
| **B8** | `metadb-tx` / Outbox Frontier | Advancing `aux_outbox_durable_index` or `QuotaRecord.applied_index_by_shard` via scalar `max` across out-of-order target ACKs can skip un-acked or un-spilled earlier tasks. | Mandated **contiguous coverage frontiers** (`contiguous_aux_acked_index` advances to `R` iff every `(idx, ord)` with `idx <= R` is durably ACKed) and `prev_uid_cursor: (u64, u16)` gap-rejection (`AuxOutOfOrderGap`) on `QuotaTable` (`consensus_and_transactions.md` §5.2, §7.3). |
| **B9** | `metadb-tx` / Spill Cleanup | Spilled `[0x07]` records had no replicated post-ACK deletion command, causing unbounded disk and snapshot growth after repeated partitions. | Added coalesced `RaftCmd::AckAuxTasks { acked_task_ids, new_contiguous_acked_index }` deleting acknowledged `[0x07][idx][ord]` keys deterministically across all replicas (`consensus_and_transactions.md` §7.3). |
| **B10** | `metadb-tx` / Directory `SetAttr` | Updating only child dentry `(pid, dir_name)` during directory `SetAttr` leaves authoritative `(dir_id, "_attr_")` and `DualModeFineGrained` `[0x04][dir_id]` records stale. | Declared `(dir_id, "_attr_")` authoritative for directory attributes; directory `SetAttr` updates `(pid, dir_name)` + `(dir_id, "_attr_")` in `1 RTT` when colocated or via Primary-Anchored `2PC` across `(pid, dir_name)`, `(dir_id, "_attr_")`, and `[0x04][dir_id]` sub-shards (`consensus_and_transactions.md` §6). |
| **B11** | `metadb-tx` / Overwrite `Rename` | POSIX `Rename { overwrite: true }` lacked explicit victim side effects (`-victim.size_bytes/-1` quota, `IndexDelete(victim.fid)`, net `0` child delta on `dst_pid`). | Specified deterministic victim expansion inside `Prepare2pc` (`Put` intent carrying net `AttrDelta`, `QuotaDelta(-victim)`, `IndexDelete(victim.fid)`, and `IndexUpsert(source.fid)`) (`consensus_and_transactions.md` §8.2). |
| **B12** | `metadb-tx` / `TxnRecord` GC | Asynchronous `CleanupTxnRecord` before all secondaries durably ACK could erase `[0x06] TxnRecord` while a secondary still held an unresolved `[0x05]` intent; secondary retries also needed an exact-once proof. | Retained `[0x06][txn_id]` with `pending_ack_keys` until every secondary participant durably ACKs `CommitSecondary2pc`/`Abort2pc`, and proved `[0x05]`-presence gating makes `CommitSecondary2pc` retries exact-once (`consensus_and_transactions.md` §8.1, §8.3). |
| **B13** | `metadb-tx` / `DirRenameLease` | A 3s `DirRenameGuard` could expire between ancestor cycle validation and `CommitPrimary2pc`, permitting concurrent directory moves to form a cycle. | Replaced unfenced guard with Raft-persisted monotonic `DirRenameLease { rename_fence_token, expire_hlc }` checked at both `Prepare2pc` and `CommitPrimary2pc` (`consensus_and_transactions.md` §8.2–§8.3). |
| **B14** | `metadb-cluster` / Split Intents | Scanning `[split_key, end_key)` (`0x01..`) misses `[0x05][target_user_key]` intents, detaching prepared 2PC keys from their locks during `ExecuteSplit`. | Specified `concat([0x05], split_key) .. concat([0x05], old_end_key)` scan in pre-split drain and logical `affinity_key` partitioning for `0x01..0x06` (`0x07` retained by `S_parent`) during `ExecuteSplit` (`sharding_and_control_plane.md` §5.3). |
| **B15** | `metadb-cluster` / Atomic Split | Single-step `ExecuteSplit` could strand child ranges if a crash occurred between parent range retirement, child Raft bootstrap, and `CellLocalManager` routing update. | Specified 3-stage recoverable split (`AllocSplitPlanRpc::Planned` -> `NODE_SHARD_REGISTRY::PendingChildBoot` + `.splitting` atomic rename + `split_child_hint` -> `ActivateSplitRpc` / heartbeat convergence) (`sharding_and_control_plane.md` §5.3). |
| **B16** | `metadb-cluster` / `conf_ver` Fence | `ShardEpoch` declared `conf_ver` alongside `version`, but fencing checks only compared `version`. | Required strict `expected_epoch == current_epoch` (`conf_ver` AND `version`) equality in pre-proposal, `apply`, and post-`ReadIndex` revalidation (`sharding_and_control_plane.md` §5.2; `consensus_and_transactions.md` §5.4). |
| **B17** | `metadb-cluster` / DualMode Re-Split | Re-splitting an already non-anchor `DualModeFineGrained` sub-shard did not specify reading existing `[0x04][P]` base metadata or deferring on active `deleting_fence`. | Specified deferring splits when `deleting_fence == true` and deriving base directory metadata from either `(P, "_attr_")` (Anchor) or existing `[0x04][P]` (non-anchor) during sub-shard splits (`sharding_and_control_plane.md` §5.3). |
| **B18** | `metadb-cluster` / ID Durability | `IdRangeAllocator` and `new_shard_id` allocation lacked explicit Raft write-before-grant durability, `request_uuid` idempotency, and leased `ShardId` block ownership. | Specified Raft write-before-grant high-water marks + `request_uuid: u128` idempotency cache on `GlobalManager` and `CellLocalManager`, including `1,024`-ID `ShardId` block leases (`sharding_and_control_plane.md` §5.3, §6.2). |

## 2. Non-Blocking Clarifications Resolved (`N1`–`N5`)

| ID | Topic | Clarification Incorporated |
| :--- | :--- | :--- |
| **N1** | Watermark Naming | Unified `lsm_flushed_index` + `attr_flushed_index` (which advance atomically together at `on_flush_durable`) into `state_flushed_index`, making `safe_purge_index = min(state_flushed_index, aux_outbox_durable_index, last_snapshot_index)` cleanly match "3-watermark purge gate" across all documents. |
| **N2** | Paginated `ListDir` Contract | Defined explicit POSIX/S3 **Keyset Continuation Semantics** (`name > after_name` per bounded linearizable page) and unconditional filtering of internal `"_attr_"` rows across SQL Templates #9–#11 (`sharding_and_control_plane.md` §5.4, §7). |
| **N3** | `QuotaRecord` Map Growth | Specified pruning of retired `ShardId` keys from `QuotaRecord.applied_by_shard` once `GlobalManager` marks a retired shard's outbox fully acknowledged (`consensus_and_transactions.md` §7.3). |
| **N4** | Phase-0 Status Vocabulary | The old shared label was `Phase 0 Approved & Goldfish-Verified`. That names a specification review, not a first-launch pass of the running tree. |
| **N5** | 16-Bit HLC Logical Overflow | Specified advancing the 48-bit `physical_ms` field by `+1ms` (yielding briefly if approaching `max_clock_drift_ms = 500ms`) and strictly forbade `u16` wrap-around (`DEVELOPMENT_PLAN.md` Phase 1; `metadb_architecture.md` §3.2). |
